A use case describes an action that a particular user performs within the GearGo system. Each role has different use cases depending on their responsibilities.

## 3.1 Customer Use Cases

### UC-C01: Browse Equipment Categories

**Actor:** Customer

**Description:**  
The customer can browse the different categories of equipment available for rental.

**Preconditions:**

- The customer has access to the GearGo website.
- The equipment catalogue is available.

**Main Flow:**

1. The customer opens the GearGo equipment catalogue.
2. The system displays the available equipment categories.
3. The customer selects a category.
4. The system displays equipment belonging to that category.
5. The customer can select an item to view more information.

**Expected Result:**  
The customer can easily find equipment based on the category they are interested in.

---

### UC-C02: View Equipment Details and Rental Rate

**Actor:** Customer

**Description:**  
The customer can view detailed information about a specific piece of equipment before submitting a rental request.

**Preconditions:**

- Equipment exists in the catalogue.

**Main Flow:**

1. The customer selects an equipment item.
2. The system displays the equipment details.
3. The system displays the equipment name.
4. The system displays a description.
5. The system displays an image where available.
6. The system displays the daily rental rate.
7. The system displays the current availability status.

**Expected Result:**  
The customer has enough information to decide whether they want to request the equipment.

---

### UC-C03: Submit a Rental Request

**Actor:** Customer

**Description:**  
The customer can request equipment for specific rental dates.

**Preconditions:**

- The customer is logged into their account.
- The selected equipment is available for the requested period.

**Main Flow:**

1. The customer selects equipment.
2. The customer chooses a start date.
3. The customer chooses an end date.
4. The system checks the equipment availability.
5. The customer confirms the rental request.
6. The system records the request.
7. The system assigns the request a pending status.
8. The system makes the request available to staff for review.

**Alternative Flow:**

- If the equipment is unavailable for the selected dates, the system informs the customer and asks them to select different dates or another item.

**Expected Result:**  
A rental request is successfully recorded and sent to staff for processing.

---

### UC-C04: View Rental Request Status

**Actor:** Customer

**Description:**  
The customer can check whether their rental request has been approved, rejected, or is still waiting for staff review.

**Main Flow:**

1. The customer logs into their account.
2. The customer opens their rental requests.
3. The system displays their previous and current requests.
4. The system displays the status of each request.
5. The customer selects a request to view more details.

**Possible statuses:**

- Pending
- Approved
- Rejected
- Cancelled
- Completed

**Expected Result:**  
The customer can clearly see the current status of their rental request.

---

### UC-C05: View Rental History

**Actor:** Customer

**Description:**  
The customer can view equipment they have rented previously.

**Main Flow:**

1. The customer logs into the system.
2. The customer opens their rental history.
3. The system displays previous rentals.
4. The customer can view equipment names, rental dates, and request status.

**Expected Result:**  
The customer can review their previous rental activity.

---

# 3.2 Staff Use Cases

### UC-S01: View Incoming Rental Requests

**Actor:** Staff

**Description:**  
Staff can view rental requests submitted by customers.

**Preconditions:**

- The staff member is logged in.
- Rental requests exist.

**Main Flow:**

1. Staff logs into the staff dashboard.
2. Staff opens the rental requests section.
3. The system displays pending rental requests.
4. Staff selects a request.
5. The system displays the customer, equipment, dates, and rental information.

**Expected Result:**  
Staff can review all relevant information before deciding whether to approve or reject the request.

---

### UC-S02: Approve Rental Request

**Actor:** Staff

**Description:**  
Staff can approve a customer's rental request after confirming that the equipment is available.

**Main Flow:**

1. Staff opens a pending request.
2. The system displays the requested equipment and dates.
3. Staff confirms that the equipment is available.
4. Staff selects the approve option.
5. The system changes the request status to "Approved".
6. The system updates the equipment's rental availability.
7. The system records the approval.

**Expected Result:**  
The rental request is approved and the equipment is reserved for the requested period.

---

### UC-S03: Reject Rental Request

**Actor:** Staff

**Description:**  
Staff can reject a rental request when the equipment cannot be provided.

**Possible reasons include:**

- Equipment is already booked.
- Equipment is damaged.
- Equipment is undergoing maintenance.
- The requested dates are not available.
- The request contains invalid information.

**Main Flow:**

1. Staff opens a pending request.
2. Staff reviews the request.
3. Staff selects "Reject".
4. Staff provides a reason for rejection.
5. The system changes the request status to "Rejected".
6. The system records the reason.
7. The customer can view the updated status.

**Expected Result:**  
The request is rejected and the customer can see that the request was not approved.

---

### UC-S04: Update Equipment Availability

**Actor:** Staff

**Description:**  
Staff can update the current status of equipment.

**Possible statuses include:**

- Available
- Reserved
- Rented
- Returned
- Damaged
- Under Maintenance

**Main Flow:**

1. Staff opens the equipment management section.
2. Staff selects an equipment item.
3. Staff selects the appropriate availability status.
4. The system saves the change.
5. The updated status is displayed to authorized users.

**Expected Result:**  
The system contains an accurate record of the current equipment status.

---

### UC-S05: Process Returned Equipment

**Actor:** Staff

**Description:**  
Staff can record when rented equipment is returned.

**Main Flow:**

1. Staff locates the rental record.
2. Staff confirms that the equipment has been returned.
3. Staff checks the equipment condition.
4. Staff records any damage if applicable.
5. The system updates the rental status to "Completed".
6. The equipment is marked as available or under maintenance depending on its condition.

**Expected Result:**  
The rental record is completed and the equipment's status is updated.

---

# 3.3 Manager Use Cases

### UC-M01: Add New Equipment

**Actor:** Manager

**Description:**  
A manager can add new equipment to the GearGo catalogue.

**Main Flow:**

1. Manager logs into the administration area.
2. Manager selects "Add Equipment".
3. Manager enters the equipment name.
4. Manager selects an equipment category.
5. Manager enters a description.
6. Manager enters the daily rental rate.
7. Manager enters relevant equipment information.
8. Manager adds an image if required.
9. Manager sets the initial availability status.
10. Manager saves the equipment.
11. The system adds the equipment to the catalogue.

**Expected Result:**  
The new equipment becomes available in the GearGo catalogue.

---

### UC-M02: Edit or Remove Equipment

**Actor:** Manager

**Description:**  
A manager can update existing equipment information or remove equipment from the catalogue.

**Main Flow:**

1. Manager opens the equipment catalogue.
2. Manager selects an equipment item.
3. Manager chooses to edit or deactivate the item.
4. If editing, the manager changes information such as:
    - Equipment name
    - Description
    - Category
    - Rental price
    - Availability
5. The manager saves the changes.
6. The system updates the equipment information.

**Expected Result:**  
The equipment catalogue contains accurate and up-to-date information.

**Note:**  
Instead of permanently deleting equipment that has previous rental records, the system could deactivate the equipment. This prevents old rental history from being lost.

---

### UC-M03: Manage User Accounts

**Actor:** Manager

**Description:**  
The manager can manage customer and staff accounts.

**Main Flow:**

1. Manager opens the user management section.
2. The system displays registered users.
3. Manager searches for a specific user.
4. Manager selects the user's account.
5. Manager can view or update permitted account information.
6. Manager can activate, deactivate, or modify the account where appropriate.
7. The system saves the changes.

**Expected Result:**  
User accounts can be maintained and controlled by authorized management personnel.

---

### UC-M04: Manage User Permissions

**Actor:** Manager

**Description:**  
The manager can control what different users are allowed to do within the system.

**Example roles:**

- Customer
- Staff
- Manager

**Main Flow:**

1. Manager opens user management.
2. Manager selects a user.
3. Manager views the user's current role.
4. Manager assigns or changes the appropriate role.
5. The system updates the user's permissions.
6. The user's access is controlled according to the new role.

**Expected Result:**  
Users can only access functions that are appropriate for their role.

---

### UC-M05: Manage Equipment Pricing

**Actor:** Manager

**Description:**  
The manager can update the rental prices of equipment.

**Main Flow:**

1. Manager selects an equipment item.
2. Manager views the current rental price.
3. Manager enters the new daily rental rate.
4. Manager confirms the change.
5. The system saves the new price.
6. The updated price is displayed in the customer catalogue.

**Expected Result:**  
Equipment pricing remains accurate and up to date.
